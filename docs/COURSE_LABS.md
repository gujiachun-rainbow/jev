# Jev 课程实验手册

配套阅读：[HTML 学员讲义](course.html)，包含逐章解释、代码片段和可交互的离线阈值实验。

配合 [课程大纲](COURSE_OUTLINE.md) 使用。命令均在项目根目录执行，先按 README 安装依赖。除“离线”明确标注的命令外，案例会调用远程 API；Agent 案例还会调用 DeepSeek，产生相应请求用量。

真实模型返回可能变化。以下“期望”是需要核对的业务行为，不是预先保证的运行结果；课堂应保留不符合预期的案例用于讨论。

学习分为基础与可选扩展：实验 1～2 直接调用 Jev；实验 3～5 的现有脚本演示 Agent 接入。基础学习可按 HTML 讲义中的普通函数、表单或状态机路径完成同类练习，不要求 DeepSeek。实验 0 的离线脚本虽导入 Agent 案例中的函数，但不会请求 Agent；需安装项目统一依赖。

## 实验 0：课前自检（离线）

```bash
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python course_threshold_lab.py
```

不要求配置 Key。需已安装项目依赖，因为离线实验直接导入案例中的业务函数。

**验收：** 测试通过；同一个 `confidence=0.65`，阈值 0.50 / 0.65 时进入 logistics，0.80 时进入 clarify。`unclear` 即使 confidence=0.99 也澄清。Noul 阈值越高，示例中待补信息越多。所有输入均为人工构造，不用于衡量 Jev 准确率。

## 实验 1：读懂一次判断（第 1～2 章）

```bash
.venv/bin/python main.py --json
.venv/bin/python case_choice.py
.venv/bin/python case_score.py
.venv/bin/python case_noul.py
```

1. 在请求中标出 state、问题 ID、instructions 和 criteria；在响应中找到同一问题 ID。
2. 用 Score 的 probabilities 验算 `sum(等级 × 概率)`，解释为何会得到小数。
3. 说明 Noul=0.3 为什么不能直接用 `bool(0.3)` 表示业务成立。

**验收：** 学员用自己的话区分“答案值”“概率分布”和“Choice / Score 的置信度”。

## 实验 2：修改标准，而不只修改提示词语气（第 3 章）

```bash
.venv/bin/python case_advanced.py
.venv/bin/python case_mixed.py
```

在 `case_advanced.py` 的 `build_case()` 中替换输入，逐条运行：

| 输入 | 应重点观察 |
| --- | --- |
| 我还没申请退货，拆封后还能退吗？ | 退货规则 |
| 退货已经签收四天，退款到哪里了？ | 退款进度 |
| 我想知道能不能退，以及退了多久能到账。 | 两类边界与当前“主诉求”定义是否充分 |

修改输入时同步更新或移除 `state.order`，避免同一订单、同一次退货和同一时间点的文字说“尚未申请退货”，结构化字段却说“商家已签收退回商品”的矛盾。“买家已签收商品”与“尚未申请退货”并不矛盾，要明确签收对象。用定义、排除条件或例子修正标准，保留前后两版结果。扩展阅读 `case_matching.py` 的动态问题构建。

**验收：** 能指出改善的是哪一个判定边界；不靠编造确定答案处理模糊样本。

## 实验 3：前置路由（Agent 扩展）（第 4 章）

```bash
.venv/bin/python agent_case_router.py "订单 DEMO-1001 到哪里了？"
.venv/bin/python agent_case_router.py "我想退货，需要什么材料？"
.venv/bin/python agent_case_router.py "帮我写一首诗。"
.venv/bin/python agent_case_router.py "查一下物流，也问一下退货规则，两件事都要处理。" --min-confidence 0.8
```

**观察链：** 输入 → 类别概率 → 置信度 → Python 分支 → 可用工具 → 实际调用 → 回复。

**期望：** 物流和售后使用各自工具；范围外请求澄清；同等重要的多诉求应按当前标准进入 unclear。若实际结果不同，记录为语义判断待分析样本。

**练习：** 增加 billing 类别和只读演示工具，列出需要同步修改的位置：criteria、`select_route()` 的允许类别、Agent 分支及测试。不要只添加类别描述。

**注意：** 重复远程调用会改变模型回答，不能把所有分支变化都归因于阈值。阈值因果演示请用实验 0 固定回答。

## 实验 4（Agent 扩展）：工具里的 Jev（第 5 章）

```bash
.venv/bin/python agent_case_jev_tool.py "预算6000元，出差办公，希望轻便，不玩游戏。"
.venv/bin/python agent_case_jev_tool.py "预算6000元，主要玩游戏，不在乎重量。"
.venv/bin/python agent_case_jev_tool.py "推荐一台办公电脑。"
.venv/bin/python agent_case_jev_tool.py "预算100元，推荐笔记本。"
```

| 场景 | 验收重点 |
| --- | --- |
| 办公 / 游戏偏好不同 | 工具参数忠于用户需求；排名与解释有依据 |
| 没有预算 | 先询问预算，不擅自假设 |
| 预算 100 元 | 返回无候选，不调用 Jev，不编造商品 |
| 预算恰好 4999 元 | Python 允许价格等于预算；可由离线测试验证 |

**练习：** 在工具中实现最低匹配门槛；当最高分也不达标时返回明确的无推荐结果。分别讨论“匹配差”和“置信度低”的不同处理方式。新增代码后用固定回答验证门槛，不要求真实模型恰好返回某个小数。

## 实验 5（Agent 扩展）：逐轮检查（第 6 章）

```bash
.venv/bin/python agent_case_followup.py
.venv/bin/python agent_case_followup.py --scenario incomplete
.venv/bin/python agent_case_followup.py --scenario complete --presence-threshold 0.9
```

**期望：** 默认先追问，再查询手册；每轮能看到三个字段的概率和当前流程。提高阈值后是否增加追问，以实际回答为准。

**练习：** 修改脚本中的 `turns`，让第二轮只回答“我使用 Safari”，第三轮再补充错误及步骤。检查送往 Jev 的 state 只含用户提供的内容。

**讨论：** 用户之后说“刚才说错了，其实是 Chrome”，累计原文方式有什么问题？设计事实更新策略，但不要把它当作当前示例已解决的能力。

## 实验 6：形成最小验证记录（第 7 章）

先为样本标注期望，再调用模型。建议用 Markdown 表格记录：

| 样本 ID | 输入及版本 | 人工期望 | 原始判断 | 阈值 | 实际分支 / 工具 | 耗时及次数 | 差异原因 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| R01 | 订单 DEMO-1001 到哪里了？ | logistics，查询订单 | 运行后填写 | 0.5 | 运行后填写 | 运行后填写 | 运行后填写 |

为每批记录补充请求模型、响应模型（若返回）、问题定义版本和日期。用量若没有采集就标为未采集，不填估计值。

- 自动处理覆盖率 = 进入业务处理分支 的样本数 / 全部路由样本数。
- 澄清率 = 进入 clarify 的样本数 / 全部路由样本数。
- 自动处理误分流率 = 进入错误业务处理分支 的样本数 / 进入业务处理分支 的样本数；分母为零时记为不适用。
- 缺信息错误放行率 = 人工标注缺信息却开放手册工具的样本数 / 人工标注缺信息的样本数。

固定模型回答调整阈值，用于评估策略；重新请求模型，用于评估端到端结果。调参与验收使用不同样本。现有不联网测试只验证业务分支，不验证 Jev 准确率或 DeepSeek 遵循提示词的程度。

## 实验 7：综合作业（第 8 章与课后）

提交可独立运行的 Jev + Python 工单流程；使用固定提示与普通查询函数即可，Agent 为选做。至少覆盖：

1. 信息不足 → 追问；补充事实后 → 重新判断。
2. 信息齐全且属于服务范围 → 查询手册并展示有依据的结果；选做 Agent 时再检查工具调用与回复。
3. 低置信度或范围外 → 澄清或演示人工接待分支。
4. 调用失败 → 明确返回失败状态，不复用虚构成功结果。

复用已有问题类型和业务函数，不要求新建复杂框架。按课程大纲提交至少 12 条标注样本及结果；说明最常见的一个错误和下一步改进方法。
